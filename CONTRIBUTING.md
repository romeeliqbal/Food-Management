# Contributing to Larder (Food-Management)

Thanks for your interest in contributing to Larder! This document explains the easiest ways to contribute and the expectations for contributions.

## Ways to contribute

- Open an issue to report a bug, suggest a feature, or ask a question:
  https://github.com/romeeliqbal/Food-Management/issues/new
- Suggest a change by opening a pull request:
  1. Fork the repository.
  2. Create a new branch for your work (git checkout -b feature/my-change).
  3. Make small, focused changes and commit with clear messages.
  4. Push to your fork and open a Pull Request against the `main` branch.
- If you prefer, open an issue first to discuss larger changes before implementing them.

## Pull request checklist

- [ ] The change is small and focused (one idea per PR).
- [ ] The HTML is valid and accessible (semantic markup, proper ARIA where needed).
- [ ] CSS is tidy and scoped (avoid global overrides where possible).
- [ ] Include a short description of what the PR changes and why.

## Code style

- This is a simple static HTML/CSS project. Keep markup clear and accessible.
- Use semantic HTML elements where appropriate (header, nav, main, footer, section, article).
- Prefer class names that describe purpose rather than presentation.

## Accessibility

- Add alt text for images.
- Ensure interactive elements are keyboard accessible and have visible focus states.
- Use ARIA attributes only when native semantics are insufficient.

## Where to ask questions

- Open an issue and tag it `help wanted` or `discussion`.

## License and ownership

By contributing, you agree that your contributions will be licensed under the same license as this project. Please ensure that any code or content you add is your own or properly licensed for inclusion.
